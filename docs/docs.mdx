After installation, import package styles at the root of your application:

```tsx
import '@mantine/core/styles.css';

```

## Usage

`DocViewer` works out the document type from `mimeType`, `fileName` or the `src` extension.
PDF, image, plain text, code and markdown files are supported.

<Demo data={demos.usage} />

Give `DocViewer` a height with the `h` prop or from its parent: documents are scrolled and fitted
inside the viewer, they do not make it grow.

## Images

Images open fitted to the viewer, never enlarged past their natural size. Zoom with the toolbar,
with `Ctrl` or `Cmd` and the mouse wheel, or with a trackpad pinch – zoom keeps the point under the
pointer in place. Drag with the mouse to move around a zoomed image.

| Key | Action |
| --- | --- |
| `+` or `=` | Zoom in |
| `-` | Zoom out |
| `0` | Fit to view |
| `r` | Rotate 90° clockwise |

Keyboard shortcuts work while the image has focus.

## PDF files

PDF files are rendered with [pdf.js](https://mozilla.github.io/pdf.js/). It is loaded only when a PDF is
opened, so apps that never display PDFs do not download it. Pages are drawn as they scroll into view.

<Demo data={demos.pdf} />

## Page thumbnails

The sidebar button in the toolbar shows a thumbnail for every page. Thumbnails are drawn as they
scroll into view, the current page is highlighted and clicking a thumbnail scrolls to its page.
Set `defaultThumbnailsOpened` to show them when the PDF opens.

```tsx
<DocViewer src="/report.pdf" pdfWorkerSrc={pdfWorkerSrc} defaultThumbnailsOpened h={600} />
```

Thumbnails are on the left by default. Readers can move them to any side with the panel position
button next to the thumbnails button. At the top or bottom they form one row that scrolls sideways.
Set the starting side with `defaultThumbnailsPosition`, or control it with `thumbnailsPosition`
and `onThumbnailsPositionChange`, for example to remember the reader's choice:

```tsx
import { useLocalStorage } from '@mantine/hooks';
import { DocViewer, DocViewerThumbnailsPosition } from 'mantine-doc-viewer';

function Demo() {
  const [position, setPosition] = useLocalStorage<DocViewerThumbnailsPosition>({
    key: 'doc-viewer-thumbnails',
    defaultValue: 'left',
  });

  return (
    <DocViewer
      src="/report.pdf"
      pdfWorkerSrc={pdfWorkerSrc}
      defaultThumbnailsOpened
      thumbnailsPosition={position}
      onThumbnailsPositionChange={setPosition}
      h={600}
    />
  );
}
```

## Links in PDFs

Links in PDF pages are clickable. Links to another part of the document scroll the viewer to that
spot without changing the page URL. Web links always open in a new tab, and only `http`, `https`,
`mailto` and `tel` links open at all. Use `onLinkClick` to see or stop them, for example to confirm
before leaving:

```tsx
<DocViewer
  src="/report.pdf"
  pdfWorkerSrc={pdfWorkerSrc}
  onLinkClick={(url, event) => {
    if (!window.confirm(`Open ${url}?`)) {
      event.preventDefault();
    }
  }}
/>
```

Screen readers read links within the document as "Go to page 3", and web links by their address.

## Rotate and search options

The rotate button turns all PDF pages a quarter turn, for scanned documents that are on their side.
It only changes the view; the file is not changed. The search bar has match case, whole words and
match accents buttons. Accents are ignored by default, so "cafe" also finds "café".

## Two pages and outline

The two pages button shows pages side by side. Set `defaultPageLayout` to open that way, with
`'two-page-cover'` for books and magazines, where the first page is on its own like a cover.

PDFs with bookmarks get an outline button that lists them; choosing one scrolls to its page.

```tsx
<DocViewer src="/magazine.pdf" pdfWorkerSrc={pdfWorkerSrc} defaultPageLayout="two-page-cover" />
```

## Print, download and full screen

The toolbar has print, download and full screen buttons. Turn them off with `withPrint`,
`withDownload` and `withFullscreen`. PDFs print with the browser's own PDF printing, images and
text from a page with only the document on it. Full screen is not offered in browsers that do
not support it, such as iPhone Safari.

## Password protected PDFs

The viewer asks for the password of a protected PDF, and says when it is wrong. To pass a
password you already have, use `pdfOptions={{ password }}`.

## Events and controller

```tsx
import { useRef, useState } from 'react';
import { DocViewer, DocViewerController } from 'mantine-doc-viewer';

function Demo() {
  const controller = useRef<DocViewerController>(null);
  const [page, setPage] = useState(1);

  return (
    <>
      <button onClick={() => controller.current?.openSearch('invoice')}>Find invoice</button>
      <DocViewer
        src="/report.pdf"
        pdfWorkerSrc={pdfWorkerSrc}
        controllerRef={controller}
        page={page}
        onPageChange={setPage}
        onDocumentLoad={({ numPages }) => console.log(`${numPages} pages`)}
      />
    </>
  );
}
```

| Prop | Description |
| --- | --- |
| `onDocumentLoad` | Called with `{ type, numPages }` for PDFs and `{ type, width, height }` for images |
| `onDocumentError` | Called with the error when a document cannot be loaded |
| `onPageChange` | Called with the PDF page that takes up most of the view |
| `onZoomChange` | Called with the scale (1 is 100%) and whether it is fitted |
| `page`, `defaultPage` | Page to show; the viewer scrolls to `page` whenever it changes |
| `defaultZoom` | A scale, or `'fit'` (the default) |
| `controllerRef` | `goToPage`, `setZoom`, `zoomIn`, `zoomOut`, `rotate`, `openSearch`, `closeSearch`, `toggleThumbnails`, `print`, `download` and `toggleFullscreen` |

## Other file types

Add file types with `renderers`. A renderer's `test` gets `{ src, fileName, mimeType, type }`
and its `render` returns the view. `DocViewerToolbar`, `DocViewerBody`, `DocViewerMessage`,
`DocViewerLoading` and `useTextDocument` give it the same toolbar, scroll area, messages and
size limit as the built-in views:

```tsx
import {
  DocViewer,
  DocViewerBody,
  DocViewerLoading,
  DocViewerRenderer,
  DocViewerToolbar,
  useTextDocument,
} from 'mantine-doc-viewer';

function CsvView({ src }: { src: string }) {
  const state = useTextDocument(src, 2_000_000);
  return (
    <>
      <DocViewerToolbar />
      <DocViewerBody focusable={state.status === 'ready'}>
        {state.status === 'ready' ? <CsvTable text={state.text} /> : <DocViewerLoading />}
      </DocViewerBody>
    </>
  );
}

const csvRenderer: DocViewerRenderer = {
  test: (file) => file.mimeType === 'text/csv' || !!file.fileName?.endsWith('.csv'),
  render: (file) => <CsvView src={file.src} />,
};

<DocViewer src="/data.csv" renderers={[csvRenderer]} />;
```

## Large documents

- Only pages near the view are drawn. Pages further away give back their canvas, text layer and
  the memory pdf.js holds for them.
- Only the parts of the file needed for the pages on screen are downloaded, when the server
  supports range requests. Searching reads every page, so it downloads the rest.
- A page canvas is kept under 16.7 million pixels (Safari's limit). Beyond that, zoomed pages are
  drawn at a lower resolution instead of going blank. Change it with `maxCanvasPixels`.
- Use `pdfOptions` for anything else pdf.js `getDocument` accepts, for example `password`,
  `withCredentials`, `httpHeaders` or `cMapUrl`. Some signed storage URLs do not support range
  requests; set `disableRange: true` for those.

```tsx
<DocViewer
  src={signedUrl}
  pdfWorkerSrc={pdfWorkerSrc}
  pdfOptions={{ disableRange: true, withCredentials: true }}
/>
```

## Text, code and markdown

Text, code and markdown files are downloaded with `fetch`, so `src` must allow it (same origin or
CORS). Files larger than `maxTextSize` bytes (2 MB by default) are not loaded; a download link is shown instead.

- **Plain text** (`.txt`, `.log`, `.csv`) is shown in a monospace font, with a toggle for line wrapping
- **Code** is shown with [CodeHighlight](https://mantine.dev/x/code-highlight/) from `@mantine/code-highlight`.
  Colors come from the highlighting adapter of your app, the same setup as for `CodeHighlight` itself.
  The language is detected from the file extension, set `language` to override it
- **JSON** opens as a collapsible tree when it is valid, with a switch to the code
- **Markdown** is rendered with GitHub flavored markdown: tables, task lists, strikethrough. Raw HTML in the file
  is not rendered, so untrusted files are safe to preview. Relative links and images are resolved against
  the markdown file url. A switch shows the source

## Text selection and search

Text in PDF pages can be selected and copied. Open search with the search button or with
`Ctrl + F` / `Cmd + F` while the document has focus. `Enter` and `Shift + Enter` move between
matches, `Escape` closes search.

Matches are highlighted with the [CSS Custom Highlight API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Custom_Highlight_API).
To change the colors, style the highlights in your global styles:

```css
::highlight(mantine-doc-viewer-match) {
  background-color: rgb(250 176 5 / 40%);
}

::highlight(mantine-doc-viewer-active-match) {
  background-color: rgb(253 126 20 / 65%);
}
```

## pdf.js worker

pdf.js parses documents in a web worker. Set `pdfWorkerSrc` to the url of the worker file from the
`pdfjs-dist` version installed in your app:

```tsx
// Vite
import pdfWorkerSrc from 'pdfjs-dist/build/pdf.worker.min.mjs?url';

// Next.js, webpack 5 and other bundlers that support new URL()
const pdfWorkerSrc = new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url).toString();
```

To set it once for the whole app, use theme default props:

```tsx
import { createTheme } from '@mantine/core';
import { DocViewer } from 'mantine-doc-viewer';

const theme = createTheme({
  components: {
    DocViewer: DocViewer.extend({ defaultProps: { pdfWorkerSrc } }),
  },
});
```

## Styling

Like core Mantine components, DocViewer takes props that set CSS variables, and every part can
be styled with the Styles API (`classNames`, `styles`, `vars` and `unstyled`).

```tsx
<DocViewer
  src="/report.pdf"
  pdfWorkerSrc={pdfWorkerSrc}
  size="md"
  color="teal"
  matchColor="grape"
  activeMatchColor="red"
  pageGap="xl"
  thumbnailWidth={80}
  radius="lg"
  tooltipProps={{ position: 'bottom', withArrow: true }}
/>
```

- `size` (`xs` to `xl`, `sm` by default) sets the toolbar height, buttons, inputs and text.
- `color` is used for pressed toolbar buttons, the current thumbnail and focus outlines.
- `matchColor` and `activeMatchColor` colour PDF search matches.
- `pageGap` and `thumbnailWidth` set the space between PDF pages and the thumbnail size.
- `tooltipProps` are passed to every toolbar tooltip, `codeHighlightProps` to the CodeHighlight
  that shows code and markdown source.
- `--doc-viewer-page-background` sets the background of PDF pages, for example a dimmer white in
  dark mode.
- Every toolbar button has the `control` selector, with `data-pressed` and `data-disabled`.

```tsx
<DocViewer
  src="/report.pdf"
  classNames={{ control: 'my-toolbar-button', toolbar: 'my-toolbar' }}
  vars={() => ({ root: { '--doc-viewer-page-background': 'var(--mantine-color-gray-0)' } })}
/>
```

## Accessibility

- Screen readers read PDF pages from their text layer. Each page is a group named "Page 2 of 3".
- The scroll area of each document can be focused with Tab and scrolled with the arrow keys. It is
  named after `fileName` and lists its keyboard shortcuts in `aria-keyshortcuts`.
- Set `alt` to describe images. Without it, the file name is used.
- The page buttons and thumbnails announce the new page, and search announces the match count.
  Load errors are announced as alerts.
- Links in markdown that open a new tab say so to screen readers.
- Thumbnails are a listbox with one tab stop on the current page. Arrow keys, Page Up, Page Down,
  Home and End move to another thumbnail and show its page; screen readers read "Page 3, 3 of 50,
  selected".
- Buttons that become unavailable, such as Next page on the last page, keep focus.
- Search announces the active match and its page once results settle.
- In Windows high contrast mode, pressed toggle buttons get an outline.

## Translating labels

Every button name, message and screen reader text can be changed with `labels`. Labels that
include a number are functions:

```tsx
import { DocViewer } from 'mantine-doc-viewer';

function Demo() {
  return (
    <DocViewer
      src="/report.pdf"
      labels={{
        nextPage: 'Nächste Seite',
        previousPage: 'Vorherige Seite',
        pageOf: (page, total) => `Seite ${page} von ${total}`,
      }}
    />
  );
}
```

`DOC_VIEWER_DEFAULT_LABELS` has the English defaults, and `DocViewerLabels` is the type of all labels.
